# 判定、报告与执行设计

## 观察对象

只比较健康基线中全部计划采样均正确、且没有请求错误的题。基线每题的 `passed` 表示全部采样通过；候选的回退观察从原始 `attempts` 重建，不能直接使用这个聚合布尔值。

默认确认策略形成如下观察：

| 首次结果 | 第二次结果 | 观察 |
|---|---|---|
| 正确 | 无需第二次 | 0，无回退 |
| 错误 | 正确 | 0，另记 flaky |
| 错误 | 错误 | 1，确认回退 |
| 错误 | 缺失或执行错误 | 未解决，不计入统计样本 |
| 执行错误、截断、拒绝 | 任意 | 未解决，不计入统计样本 |

离线使用相同的前两次结果，额外重复采样只进入诊断统计。关闭确认时使用首次有效结果，失败概率的含义随之改变。独立条件下两次失败概率为单次失败概率的平方；实际调用可能相关，因此不能直接把这个关系当作生产保证。

## 在线顺序检测

默认比较 `p0=0.02` 与 `p1=0.20`，其中 p 是上述策略定义的观察事件概率，而不是未经确认的单次答错率。每次有效观察更新：

```text
LLR += log(p1/p0)                 当观察为 1
LLR += log((1-p1)/(1-p0))         当观察为 0
upper = log((1-beta)/alpha)
lower = log(beta/(1-alpha))
```

达到最小样本量后，LLR 不小于 upper 判回退，不大于 lower 判稳定；达到最大样本数或耗尽题目仍无结论时为 inconclusive。默认 alpha=0.05、beta=0.10、最少 8 题、最多 32 个有效观察。连续 12 个无回退观察达到稳定边界。状态到达终点后禁止继续追加样本，避免回放改写已经停止的结论。

抽样默认按类别分层随机排列，自动生成且保存 seed 与实际观察顺序。模型参数 seed 与抽样 seed 是两个独立配置。早停意味着本轮没有检查全题包；报告公开 eligible、observed、counted 及类别覆盖，周期性 deep 检查补足覆盖。

## 离线全量比较

离线默认利用全部有效配对，不执行顺序早停，也不按 max_samples 丢弃后半段数据。设有效样本 n，回退数 k：

```text
regression_p_value = P(X >= k | X ~ Binomial(n, p0))
stable_p_value     = P(X <= k | X ~ Binomial(n, p1))
```

达到最小样本量后：仅前者不大于 alpha，判 regressed；仅后者不大于 beta，判 stable；两者都未达到或同时达到阈值，判 inconclusive。同时达到意味着数据更符合 p0 与 p1 之间的中间区域，不强行归入端点假设。概率用对数形式的二项概率和计算，避免直接计算组合数及大整数幂。

这是固定样本规则，与 SPRT 的边界不同。因此在线和离线的观察定义一致，最终决策不必一致。`compare --replay` 显式重放题包顺序下的 SPRT，仍保存 full_verdict、全量摘要以及未参与早停判定的观察数量；该模式不是对任意历史随机顺序的自动复原。

## 质量门槛与退出状态

统计输出保存在 capability_verdict；最终 verdict 还受可用性和覆盖约束。执行中止、错误/未解决比例超过阈值、缺少必需类别的有效样本，都会阻止 stable。请求错误不增加回退计数，已有明确的回退证据仍保留。

命令行遇到实际执行错误时返回 1；regressed 为 2，inconclusive 为 3，成功为 0。能力结论与执行状态都写入文件，不能只通过一个退出码还原所有信息。quick 使用 smoke_pass、smoke_fail、smoke_error，不产生基线回退结论。

## 报告与可比性

schema v2 保存原始尝试、判分结果、完成原因、usage、HTTP 尝试及各层摘要。加载基线或候选时验证版本、模式、唯一 ID、题包成员、采样完整性和汇总一致性，并用原始输出重新检查判分；不接受重复 ID 的静默覆盖。

调用配置包含接口类型、规范化端点、模型、system prompt 摘要、temperature、模型 seed、token 参数、reasoning effort、每题有效输出预算和评分器版本。题包另有 SHA-256 摘要。配置本身也有规范化摘要；这些摘要用于防止意外不一致，不是签名或来源认证。

默认拒绝不兼容比较；显式 allow-config-mismatch 允许有意对比，并保存差异。旧报告没有这些字段，无法可靠迁移，要求重新建立基线。历史 Codex CLI 的批量冒烟测试属于不同调用方式，不可作为直接 API 基线。

## API、预算和并发

HTTP 客户端使用标准库。所有请求禁止自动重定向；错误保存前移除当前密钥。严格验证输入数值、响应对象、choices、message、finish_reason 与 usage，异常协议归入 APIError。超过 60 秒的 Retry-After 会中止本轮并保存原因，交由后续调度重试，避免无限等待或提前请求。

输出截断、过滤、拒绝及非文本完成状态保留为独立状态。修改输出预算属于调用条件变化，应重新建立基线。响应返回的实际模型和 system fingerprint 用于诊断，不能代替客户端请求参数的可比性校验。

全量任务使用最多 workers 个在途题目；统计自适应检查保持顺序。客户端锁保护共享 HTTP 请求计数，包括重试和确认。预算耗尽或不可恢复错误后停止提交新题，并收集已经发出的请求结果；报告原子写入，避免替换成半份 JSON。

latency_ms 包括重试及等待；token 统计保留嵌套明细。未返回 usage 或请求超时的消耗标为未知。deadline 在发送、退避、分块读取和返回前检查，socket timeout 随剩余时间调整；同步 DNS 与响应头读取仍受底层网络超时行为约束，不是操作系统级硬终止。

## 校准与适用范围

这些检验依赖独立、同分布等假设，真实题目难度、类别、服务路由和重复采样往往相关。分层抽样、确认策略、题包、评分器或参数改变后，应使用带健康/退化标签的历史数据回放，分别观察误报、漏报、证据不足和调用成本。默认阈值不是对总体模型能力的无条件置信保证。

内置题包属于基础能力冒烟测试，不能覆盖长上下文、多轮交互、工具调用、视觉与所有专业业务。新增业务题应来自真实失败模式，由独立方法核验答案，并在健康版本和已知退化版本上确认区分度。增加题量本身不能保证效果。
